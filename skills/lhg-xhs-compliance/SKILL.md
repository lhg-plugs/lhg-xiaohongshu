# lhg-xhs-compliance：小红书笔记合规自查

> 目标：笔记发出去不违规、不限流、不被投诉。种草笔记的生死线是广告法和平台营销号判定。
> 核心纪律：**先跑脚本（机器），再做复核（人）；blocker 不清零，不许说"可以发了"。**

## 1. 何时使用

- 笔记定稿、准备发布前 → 跑全流程（对应 `/xhs-audit`）
- 写完想快速看一眼 → 只跑第 2 步（脚本），10 秒出结果
- 改完 blocker 回归 → 只跑脚本确认消失

## 2. 第一步：跑确定性审计脚本（必做）

用你所在平台执行本地脚本的方式，运行插件自带的审计脚本：

```
python3 <插件目录>/scripts/audit/xhs_audit.py --target <笔记文件或目录> [--format json|text] [--fail-on blocker|warning|nit]
```

脚本能力（16 条规则，零第三方依赖）：

| 类别 | 规则 | 说明 |
|---|---|---|
| 极限词 XHS-LIMIT | 2 条 | 广告法极限词（最/第一/国家级/首个/顶级）blocker；功效断言词（根治/治愈/100%有效/保证）warning |
| 标题 XHS-TITLE | 3 条 | 无标题 warning；标题超 20 字 warning；标题无吸引点（无数字/emoji/悬念符号）nit |
| 标签 XHS-TAG | 2 条 | 标签不在 3~10 个 warning；疑似堆砌无关大词 warning |
| 封面 XHS-COVER | 3 条 | 封面缺失 blocker；比例非 3:4 blocker；尺寸非 1242×1660 warning |
| 正文 XHS-BODY | 3 条 | 正文过短（<100 字）/过长（>1000 字）warning；错别字 warning；AI 味信号 nit |
| 营销 XHS-AD | 3 条 | 联系方式（微信/电话）warning；绝对化促销（全网最低/仅此一天）warning；疑似硬广（全文无"我"）nit |

- 有 blocker 时脚本以非零 exit code 退出——这是设计，不是 bug。
- `--fail-on` 默认 `blocker`；品牌商单建议用 `warning`（更严）。
- 脚本只做"机器可判定"的事：营销号限流风险、广告标识、语气真假，它判定不了，那是第 4 步的事。

## 3. 第二步：分级处理

| 级别 | 定义 | 处理 |
|---|---|---|
| blocker | 发出去违规：广告法极限词、封面比例错误 | 必须改，不许豁免，不许为清零改脚本 |
| warning | 大概率被限流/投诉：标题过长、标签异常、功效断言、联系方式 | 逐条修；修不掉的写进报告"已知风险"并说明理由 |
| nit | 洁癖项：标题吸引点、AI 味信号 | 顺手修 |

修一条用脚本复查一条。极限词改法：删掉，或换成可验证的具体表述（"最好用"→"我用过 3 款里最顺手的"）。

## 4. 第三步：人工复核（脚本覆盖不到的）

### 4.1 营销号限流风险
小红书对营销号的判定是综合的，单篇合规不代表账号安全。自查：

- 最近 5 篇笔记里，硬广（全文无真实体验细节）有几篇？≥ 3 篇 → 本篇建议改成软广或隔 2 天再发。
- 是否每篇都挂商品链接/留联系方式？是 → 本篇去掉，留一 gathering 口。
- 评论区是否有"求链接""怎么买"的托式评论？有 → 删掉，平台能识别。

### 4.2 广告标识
- 品牌合作/商单：按平台规范标注"品牌合作"或"广告"。**不标注被查到，比标注了限流更严重。**
- 自费购买：建议写"自费购买"，一句话的事，可信度+50%。

### 4.3 功效表述复核
把正文里所有"效果句"挑出来，逐句问：这是"我体验到的"还是"产品保证的"？后者一律改成前者。

```
❌ "7 天去黑头，顽固黑头一扫光"（保证口吻）
✓ "我用了 7 天，黑头看着少了一半"（体验口吻）
```

### 4.4 封面人工看
脚本只验尺寸，人工看三眼：缩略图下大字认得清吗？主体完整吗？和标题呼应吗？有一眼不行就重做。

### 4.5 敏感类目加码
美妆/食品/母婴/医疗相关：功效词一个不许留；有"治疗/调理/功效"暗示的，整句删掉。**类目越接近身体，措辞越保守。**

## 5. 第四步：输出报告

```markdown
# 笔记自检报告（YYYY-MM-DD）
## 结论：建议发布 / 不建议发布
## blocker（n）：已修 n，剩余 n
- [规则ID] 文件:行 —— 说明 —— 状态（已修/需人工）
## warning（n）：已修 n，已知风险 n（理由）
## 人工复核：营销风险（通过/不通过），广告标识（已标/不涉及），功效表述（通过/不通过），封面（通过/不通过）
## 发布 checklist
- [ ] 标题 ≤ 20 字  [ ] 标签 5~8 个  [ ] 封面 1242×1660  [ ] 广告标识  [ ] 定时  [ ] 评论区话术
```

报告存为 `notes/audit-YYYYMMDD.md`。结论"不建议发布"必须写清卡在哪一条。

## 6. 极限词库维护说明

脚本内置的极限词库是 2026-10 快照（约 40 词）。广告法执法口径和平台审核尺度会变：

- **加词**：发现漏报（如新型擦边词），按 skill 反馈渠道提 issue，附原文截图/复现文本。
- **减词**：确认误报的，同样提 issue，说明上下文，维护者评估后移除。
- **版本**：词库变更随插件 minor 版本发布，更新日志写清增删了哪些词。

**不要自己改脚本阈值来"清零"**——那是作弊。词库问题走 issue，个案问题改文案。

## 7. 误报处理

1. **判断三问**：这个词在上下文里真的违规吗？规则的本意是什么？按规则改了会不会伤害表达？
2. **确认误报**：在报告"已知风险"区写清理由（如"最高"出现在"最高只卖 99"的价格表述，非极限词），并记一笔。
3. **拿不准**：按 blocker 处理。**误报的代价是改几个字，漏报的代价是违规下架。**
4. **规则本身有问题**：附最小复现文本提 issue（见第 9 节）。

## 8. 高频翻车案例（自查时对照）

小红书种草最常见的 4 种翻车：

1. **极限词翻车**：标题写"全网最好用的粉底液"→ 被职业打假人截图举报，品牌方连带受罚。
   防："最/第一"出现即 blocker，换成"我的体验"口吻。
2. **功效断言翻车**：美妆笔记写"7 天祛痘根治"→ 医疗广告违规，下架 + 账号扣分。
   防：4.5 节加码审查，效果句全部改成体验口吻。
3. **营销号限流**：新号连续 7 天每天 3 篇硬广 → 流量从 5000 跌到 200，且不通知。
   防：4.1 节评估发文节奏，硬广和生活内容 3:7 搭配。
4. **商单未标识**：品牌合作没标"广告"→ 被平台查到，笔记下架 + 品牌方被约谈。
   防：合作必标识，自费写"自费购买"，一句话的事。

**记住**：下架是最轻的代价。医疗/金融/涉政三类，宁可不过审不发，不许带着 blocker 发。

## 9. 反模式

- ❌ 只跑脚本不做人工复核——脚本看不出"这篇像营销号"
- ❌ "warning 太多了，先发了再说"——warning 就是未来的限流理由
- ❌ 极限词换成拼音/谐音（"最"→"zui"）——平台一样识别，还显得心虚
- ❌ 商单不标广告标识——被查到比限流严重得多
- ❌ 医疗/美妆功效断言——这是 blocker，不是可选项

## 10. 自检与反馈

跑完本 skill 自问：

1. 脚本真的跑了吗？→ 没跑不算做。
2. blocker 清零或全部列入"需人工处理"了吗？→ 有遗漏就补。
3. 人工复核 5 项逐项有结论吗？→ 结论要有依据。

标准冒烟用例：对插件自带的 `fixtures/` 跑脚本，确认坏 fixture 的 blocker 全命中、好 fixture 零 blocker（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-xiaohongshu/issues，正文写清"输入 → 错误输出 → 期望输出"。规则误报/漏报请附最小复现文本。
