# /lhg-xiaohongshu:xhs-audit —— 笔记发文前自检

用户输入在 `$ARGUMENTS` 中：`<笔记文件或目录> [--strict]`。缺省为 `notes/` 下最新的一篇笔记。
`--strict` 把 warning 也当 blocker 处理（品牌合作商单/医疗美妆题材建议开）。

按 `lhg-xhs-compliance` skill 全流程执行；结论只能是"建议发布"或"不建议发布"。

## 流程

### 1. 跑脚本（必做）
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/xhs_audit.py --target <笔记> --format text
```
记下 blocker / warning / nit 的数量与明细（含行号、规则说明）。

### 2. 分级处理
- **blocker**：广告法极限词（最/第一/国家级/首个）、封面比例非 3:4——必须改掉，不许豁免。
- **warning**：标题超 20 字、标签不在 3~10 个、功效断言词、封面尺寸非 1242×1660——逐条修；修不掉的写进报告"已知风险"。
- **nit**：顺手修。
- 修一条用脚本复查一条；**不许**为清零改脚本规则或阈值。

### 3. 人工复核（脚本覆盖不到的）
- [ ] 营销号风险：全文广告味是否过重（连续 3 篇硬广会被限流，建议软广比例）
- [ ] 广告标识：品牌合作/商单是否按平台要求标注"广告"/"品牌合作"
- [ ] 功效表述：是否全是"我的体验"口吻，有无绝对化断言
- [ ] 封面人工看：标题大字手机端可读吗？人物/产品主体被裁了吗？
- [ ] 评论区预案：置顶评论、差评回复话术是否准备好

### 4. 输出报告
```markdown
# 笔记自检报告（日期）
## 结论：建议发布 / 不建议发布
## blocker（n）：已修 n，剩余 n
## warning（n）：已修 n，已知风险 n
## 人工复核：x/5 通过
## 发布 checklist：标题□ 正文□ 标签□ 封面□ 广告标识□ 定时□
```
报告存为 `notes/audit-YYYYMMDD.md`。结论"不建议发布"时必须写清卡在哪一条。

## 红线提醒

- 本命令只做"建议"，**不自动发布**。发布永远由用户亲手完成；需要登录账号的操作一律不代劳。
- 脚本词库是启发式：误报按 warning 处理并记录，不许直接忽略 blocker；拿不准的按 blocker 处理。
